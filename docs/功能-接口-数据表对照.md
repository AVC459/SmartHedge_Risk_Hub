# SmartHedge_Risk_Hub · 功能 — 接口 — 数据表 对照文档

> 用途：把「前端某个页面/按钮」→「调用的后端接口」→「实际读写的数据库表」一一对应起来，方便答辩讲解与自查。
>
> - 服务端口：`8084`（`application.yml`）
> - 数据库：`smarthedge_risk_hub`（MySQL，连接配置见 `src/main/resources/jdbc.properties`）
> - 统一返回体：`Result<T> = { success, code, msg, data, total }`
> - 分页约定：统一使用 `keyword` / `page` / `size` 三个参数

---

## 一、数据库表总览

| 表名 | 中文含义 | 对应实体类 | 维护入口 |
| --- | --- | --- | --- |
| `sys_user` | 系统登录用户 | `SysUser` | 登录页（新建） |
| `trading_variety` | 交易品种 | `TradingVariety` | 基础数据 → 交易品种 |
| `exchange` | 交易所 | `Exchange` | 交易所模块（CRUD + 分页，走 Redis 缓存） |
| `industry` | 行业（字典） | `Industry` | 随交易品种只读展示 |
| `supply_category` | 供货品类 | `SupplyCategory` | 基础数据 → 供货品类 |
| `origin_dict` | 产地字典 | `OriginDict` | 基础数据 → 产地字典 |
| `operator` | 经营者 | `Operator` | 基础数据 → 经营者 |
| `spot_products` | 现货商品 | `SpotProduct` | 现货与供应商 → 现货商品 |
| `supplier` | 供应商 | `Supplier` | 现货与供应商 → 供应商档案 |
| `supplier_category_rel` | 供应商-供货品类关联 | `SupplierCategoryRel` | 供应商档案（随新增/编辑/删除联动） |
| `futures_contract` | 期货合约 | `FuturesContract` | 衍生品合约 → 期货合约 |

> 智能问答（AI）模块**不使用 MySQL 表**，数据落在项目根目录 `knowledge/`（原始文档）与 `data/vectorstore.json`（向量库）中。

## 四、表间关联关系

```
trading_variety.exchange_id ──→ exchange.exchange_id
trading_variety.industry_id ──→ industry.industry_id
futures_contract.variety_id ──→ trading_variety.variety_id
spot_products.origin_id     ──→ origin_dict.origin_id
supplier.operator_id        ──→ operator.operator_id
supplier_category_rel.supplier_id ──→ supplier.supplier_id
supplier_category_rel.category_id ──→ supply_category.category_id
```

另外三张「字典表」`exchange` / `industry` / `origin_dict` 只被关联查询读取，前端没有单独的增删改入口。

**缓存设计**

| 缓存 key | 内容 | TTL | 失效时机 |
| --- | --- | --- | --- |
| `master:exchange:list` | 交易所全量列表 | 10 分钟 | 新增/修改/删除后主动删除 |
| `master:tradingvariety:list` | 品种全量列表（含交易所、行业） | 10 分钟 | TTL 到期 |

Redis 不可用时 `HotDataCache` 会进入 60 秒熔断窗口，期间自动回退数据库，不影响业务。

## 五、说明与已知限制

1. **登录方式**：Session 会话（Cookie `JSESSIONID`），前端所有请求均为同源 `credentials: same-origin`，无需额外配置跨域。
2. **路由守卫**：应用启动时先请求 `/api/user/current`；未登录只渲染登录页。会话失效时 API 层会派发 `hr-unauthorized` 事件，前端自动退回登录页。
3. **密码为明文存储**（课程演示用途），生产环境应改为 BCrypt 等加盐哈希。
4. 后端**未对业务接口做强制的登录拦截**，当前保护在「前端路由守卫」层；若需要服务端强制鉴权，可追加一个 `HandlerInterceptor` 拦截 `/api/**`（放行 `/api/user/**`）。
5. 分页为**后端内存分页**（Service 里 `subList`），数据量大时应改为 MyBatis-Plus 物理分页。
6. 供应商「编辑」时，后端 `findAllSupplierWithOperator` 不返回该供应商已关联的 `categoryIds`，因此编辑弹窗的「供货品类」默认是空的；若直接保存，会把原有关联替换为空。如需完整回填，可新增接口 `GET /api/supplier/relations/{supplierId}` 返回其品类 ID 列表。
7. **注册开放**：`/api/user/register` 未加邀请码或审批，注册成功即为启用状态，角色默认 `operator`；如需限制可在接口内加校验。
8. **知识库统计实时刷新**：知识库问答页每 5 秒轮询一次 `/api/ai/kb/stats`，并在切换到「知识库管理」页签时立即刷新，保证「N 篇 / M 个切片」与实际一致。
9. **Redis 缓存**：需本机启动 Redis（默认 `localhost:6379`）；未启动时自动降级为直查数据库，功能不受影响。
10. **交易所模块**：当前只提供后端接口，前端没有独立页面；可访问 `/api/exchange/list` 或 `/api/exchange/page` 验证。
11. **分页方式**：交易所等字典模块为内存分页（全量查询后 `subList`），数据量大时应改为 MyBatis-Plus 的 `IPage` 物理分页。
